## สรุปงานที่ทำ
Gated the login Quick Demo panel (`Quick Demo Access` / `เข้าระบบทดลอง`) so it renders only when `NEXT_PUBLIC_DEMO_MODE` is exactly `true`. Unset or any other value hides it (fail closed). The credential module is swapped out of the webpack client and server graphs unless the flag is on, so those literals are not in the production build output by default.

## ไฟล์ที่สร้าง/แก้ไข
- `frontend/next-app/components/auth/login-form.tsx` - render the panel only when the flag is exactly `true`
- `frontend/next-app/components/auth/demo-accounts.ts` - credential list, imported only by the real panel
- `frontend/next-app/components/auth/demo-quick-access.tsx` - panel UI
- `frontend/next-app/components/auth/demo-quick-access-off.tsx` - empty stand-in used when the flag is off
- `frontend/next-app/next.config.mjs` - inline the flag as `true` or empty, and replace the panel module when off
- `frontend/next-app/tests/components/login-form.test.tsx` - fail-closed cases plus the enabled fill path
- `frontend/next-app/.env.example` - documents `NEXT_PUBLIC_DEMO_MODE`
- `AGENTS.md` - env section plus a follow-up to remove demo users from the prod seed/DB

## ข้อควรระวัง / หมายเหตุ
`NEXT_PUBLIC_*` is inlined at build time. Changing the flag requires a redeploy. Values other than the exact string `true` (`TRUE`, `1`, `yes`, whitespace) stay hidden.

Verification: Vitest login-form tests; `npm run lint` (pre-existing warnings only); `next build` typecheck passed. A full `tsc --noEmit` still reports pre-existing errors in older tests. Production builds were scanned for the demo account emails and the password literal: absent everywhere under `.next-build` when the flag is unset, present in the login client chunk when it is `true`. Headless Chrome against `next start` showed the role buttons only on the flag-on build.
